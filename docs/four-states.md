# 四态契约：把「没查」和「查了没有」分开

## 问题

三态系统（found / suspected / absent）里，`absent` 同时承担了两个含义：

1. 「我查了，范围内没有」——这是**结论**。
2. 「我没有查」——这是**没有结论**。

二者混住时，系统会自动挑对自己有利的那个解释：需要显得诚实 → 说「我查过没有」；被追问为什么没提 → 说「我没查」。
**同一个返回值，两种事实。** 这是所有「假装记得 / 假装不记得」的结构性来源。

## 契约

| 状态 | 含义 | 允许的渲染 | 禁止 |
|---|---|---|---|
| `not_checked` | 没有触发检查 | 「没查」/不提及 | 声称查过、携带 searched 范围、给出 absent 的理由 |
| `found` | 查到本人陈述，且引文可逐字定位 | 引用原话 + 时间 + 出处 id | 引用转贴/助手消息/问句 |
| `suspected` | 查到相关，但不满足 found 的证据资格 | 「你提过相关的，但我不确定是不是同一件事」 | 包装成「沾边的个人经历」 |
| `absent` | 查过了，范围内没有 | 「我查了，没找到」+ 实际搜索范围 | 用于「没查」；无范围却声称查过 |

## 三条实现要求

1. **触发留痕**：每次检查记录 `trigger_reason` ∈ {`time_word`, `memory_question`, `object_hit`}。
   否则「漏召回」和「未触发」无法区分——而这两种失败要用完全不同的办法修。
2. **证据资格独立于 role**：`role=user` 只回答「谁发的」。还需要第二问「谁在主张」（本人陈述/转述/引用/假设/来源不明），和第三问「它能支持什么」（可作依据/仅线索/不可用）。
3. **输出侧另有一张清单**：发出前校验比对的是「本轮实际在上下文里的东西」——注入的记忆 **加上** 当前对话本身；绝不能是「库里有就算有」。

## 两条经验规则

- **判不准时标「来源不明」，权限按转述处理。** 不能说成「这就是转述」——那是另一种假装确定；也不能说成「这就是他说的」——那是我要防的病。
- **拦下假 found，不等于必须补一个 suspected。** 没有合格证据就 `absent`。为了让结果看起来「有用」而编一个中间态，是同一个病的轻度版本。

## 反例（真实发生过）

- 问「我上周提的那个盘呢」→ 返回 `found`，证据是这句问话本身（案例 2）。
- 与旧事无关的日常提问 → 返回 `absent` + 「已查范围：全部原话」，而它压根没查（案例 5）。
- 五条自然提问四条 `not_checked`，其中两条本应命中（案例 6）。

## 一句话

**能分清四种「没有」，才敢说一句「有」。**
