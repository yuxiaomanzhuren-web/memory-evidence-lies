# 失败分类学：十种「她明明不该说，却说出口了」

这些案例都来自一个长期运行的个人记忆系统（原话库 → 提炼条目 → 门闸检查 → 提示词注入 → 发出前校验），**都在真机上真实发生过**，且至少复现过一次。

人名、对象名、时间、具体食物等已全部改写；**结构、标签和错误形状保留原样**。改写的目的是可复现，不是保护谁的面子。

## 案例 1｜转贴文档被当成本人陈述

- 输入：用户把一份第三方报告整段粘贴进来。
- 错误输出：`found`，证据是报告里的一个文件名。
- 为什么错：`role=user` 只说明「谁按的发送键」，不说明「谁在主张」。转贴是**他带来的东西**，不是**他说的话**。
- 正确行为：`found` 的引文必须来自本人陈述；转贴最多作线索，且要标明「查到一份转贴，不作为证据」。

## 案例 2｜问题本身被当作证据

- 输入：「你还记得我上周提的那个盘吗」
- 错误输出：`found`，证据就是这句问话。
- 为什么错：问句不含对过去事实的任何声称，拿它当证据等于自证。
- 正确行为：候选只取本人**陈述句**；问句、指令、祈使句一律不入选。

## 案例 3｜助手自己的回复被当作证据

- 输入：「我早饭是不是吃了某物」
- 错误输出：`found`，证据是助手几小时前复述过的一句话。
- 为什么错：助手的话不是用户的记忆，它可能是幻觉的产物——用幻觉验证幻觉。
- 正确行为：只取 `role=user`；助手消息只能作**对话上下文出处**（证明「刚说过」），不能作**事实证据**。

## 案例 4｜一处匹配放行整条消息

- 输入：一条要发出的回复，前半句有真实出处，后半句是编的。
- 错误输出：`allowed=true`（因为前半句匹配成功）。
- 为什么错：一条真引用给整段假话背了书。校验粒度错在「按消息」，应在「按引用」。
- 正确行为：逐条验；被拦时**只剥掉无出处的那一句**，不许整条静默丢弃。

## 案例 5｜把「没查」说成「查了没有」

- 输入：一句与过往无关的日常提问。
- 错误输出：`absent` + 「已查范围：全部原话」。
- 为什么错：它压根没查，却声称查过并给出范围。这是**用检索的存在感冒充检索的结果**。
- 正确行为：四态分开，`not_checked` 不得渲染成 `absent`，更不得携带「已查范围」。

## 案例 6｜敲钟太窄：问题根本没被检查

- 现象：五条自然提问，**四条返回 `not_checked`**。
- 原因：触发条件只认时间词（昨天/上次/之前）与固定句式；「我今早是不是没吃早饭」「某物到底好不好吃」这类既无时间词也无模板，于是从来没被检查过。
- 为什么危险：所有「防假」的闸门都建在「会被触发」之上。触发不到 = 闸门不存在。
- 正确行为：触发两条腿——① 时间指代/记忆提问；② **疑问句 + 库中存在相关对象**。并记录 `trigger_reason`，把「漏」和「没触发」分开统计。

## 案例 7｜兜底句冒充助手本人

- 现象：校验失败、自动重写也失败后，系统代发一句固定话术，语气与平时一致。
- 为什么错：对方收到的是一句**不是她说的、却被当成她说的**话。信任伤害比道歉更大。
- 正确行为：兜底句必须自证身份（前缀/标记），且日志留 `fallback_text`。

## 案例 8｜兜底后整轮静音

- 现象：兜底句发出后，同一轮后续所有消息被当作「重复」丢弃，接口返回 `ok: true, sent: 0`。
- 为什么危险：**静默失败**。使用者只看到「她突然不说话」，看不出是系统坏了。
- 正确行为：去重只比较**这一条**是否等于刚发过的兜底句；被压制必须返回显式错误。

## 案例 9｜陈述句触发旧事检索

- 输入：「今天早饭吃了豆腐脑」（一句陈述）。
- 错误输出：去翻上周同名的旧事，并给出 `suspected`。
- 为什么错：没人问过去。它自己把陈述当成追问，于是「呼应」变成了「编关联」。
- 正确行为：陈述句不触发；要呼应旧事，必须由使用者先给出指向。

## 案例 10｜已了结的代价还在生效

- 现象：一条「做过但被拒绝」的代价记录，用户已明确说「这事过去了」，系统仍按未了结处理。
- 为什么错：把「时间流逝」当成「已了结」，或干脆没有「了结」这个字段。
- 正确行为：代价记录带 `resolved_at`；了结只有两种来源——本人明确说了结，或被一条更晚的、明确表达转变的原话取代。不按经过多久推断。

## 一句总结

十个案例里，**八个**不是「检索没找到」，而是**「找到了不该找的东西」**或**「没找却说自己找了」**。
所以第一优先级不是提高召回率，而是让每一种「没有」都能被区分开。
